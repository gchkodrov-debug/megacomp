For each benchmark website, investigate:

* Visual design and art direction.
* Typography and layout systems.
* Animation and motion.
* Cinematic storytelling.
* 2D graphics.
* 3D graphics and WebGL, if present.
* Video production and playback.
* Scroll-controlled interactions.
* Navigation and user journeys.
* Responsive mobile design.
* Application architecture where publicly observable.
* Browser rendering and performance.
* Loading and asset-delivery strategies.
* Accessibility.
* Interactive product functionality.
* Publicly observable technical dependencies.
* Security-relevant design patterns without intrusive testing.

Inspect the live experience, publicly served assets, browser behavior, and available technical documentation.

Distinguish verified findings from educated hypotheses.

Do not bypass security, access private systems, copy proprietary code, or reuse protected creative assets.

If Sorana.com is inaccessible or cannot be meaningfully inspected, report that limitation and request clarification rather than inventing findings.

2. CREATE A TECHNICAL CAPABILITY MAP

For every benchmark, answer:

1. What makes the experience distinctive?
2. Which technical skills would be required to create an original experience with comparable functionality and sophistication?
3. Which of those skills does our crew already possess?
4. Which skills remain unproven?
5. Can our crew explain the relevant architecture?
6. Can our crew reproduce the underlying technique using original assets in a small, isolated demonstration?
7. Can our crew debug and optimize that demonstration?
8. Can our crew defend its engineering decisions?

Do not confuse familiarity with mastery.

The captain must select only the exercises needed to establish capability.

Do not produce an unauthorized OneJobKits website or a full replica of any benchmark.

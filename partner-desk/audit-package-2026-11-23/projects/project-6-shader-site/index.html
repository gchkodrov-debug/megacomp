How the dissolve works

Every pixel is given a fixed height from a noise field — four octaves of value noise, summed. The transition is one number, a threshold, sweeping from below the field's floor to above its ceiling. A pixel shows the old scene while its height stands above the threshold and the new scene once the threshold passes it; where the two are within a hair, the pixel burns gold. The whole effect is this comparison, run a million times in parallel:

float h = fbm(p * 5.0) * 0.85 + vnoise(p * 22.0) * 0.15;   // the pixel's fixed height
float t = uProgress * 1.12 - 0.06;                          // the sweeping threshold
vec3 col = mix(toC, fromC, step(t, h));                      // below: new · above: old
col = mix(burnGold, col, smoothstep(0.0, 0.035, abs(h - t))); // the burning edge

How the swirl works

Each scene's coordinates are rotated around the centre by an angle that grows with the sine of the progress — strongest mid-transition, zero at both ends — and falls off with distance from the centre. The outgoing scene winds one way, the incoming unwinds from the other, and a radial mask hands the picture over at the peak. No pixel is ever blended from a third, invented image; both scenes are only ever re-addressed.

The fallback is shipped, not promised

Before the stage is built, the pack asks the browser for a throwaway WebGL context. No context, no shader stage: the two scenes stand as stacked images and the same buttons crossfade them with CSS. The readout names the mode the page is actually in. The exam harness visits this page twice — once normally, once with WebGL disabled — and grades both.
